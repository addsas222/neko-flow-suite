# 更便宜的一级

## 阶梯

先问最便宜的问题，在第一条成立的地方停下：

| 级别 | 问题 |
| --- | --- |
| nothing | 能不能不改代码就解决这个问题 |
| one-line | 一个已经存在的调用能不能解决 |
| stdlib | 标准库有没有现成的 |
| existing-dep | 已经装了的包能不能解决 |
| new-dep | 值得为它引入一个新依赖吗 |
| new-service | 真的需要新的进程或服务吗 |
| framework | 真的需要新框架吗 |

更便宜的一级能成立，就用它；不能成立，就用一句话说明为什么不能。

## 删除清单

收尾前，删掉你加进来但没有任何真实消费者的东西：为不可能发生的情况预留的
分支、没人读的形参、只有一个调用方的包装、只有一个取值的配置、标准库已经
提供的能力、解释绕行的注释。

## 不可越过的安全边界

删除时保留全部安全护栏：授权与信任边界校验、输入校验、隔离、数据丢失防护、
存储格式兼容、并发与清理所有权、可达性基础。把其中任何一项关掉，本身必须
是一个被明确授权的目标，而不是简化的副产品。

## 记录推迟

当你明知故犯地推迟某件事时，留下 `ponytail: <你没做什么>`。推迟是可以的；
忘记不行。

## 交给外部 Agent

`ponytail_ruleset_for_host` 会返回某个宿主的规则文件名与可直接粘贴的规则文本：

| 宿主 | 目标文件 |
| --- | --- |
| claude | `CLAUDE.md` |
| cline / cline-code | `.clinerules` |
| codex / agents | `AGENTS.md` |
| cursor | `.cursor/rules` |
| windsurf | `.windsurfrules` |
| generic | `RULES.md` |

## 交接纪律

报告你删了什么、验证了什么、还有什么没被证明。一次小范围测试通过，不等于
运行时、部署或用户验收。
