# 工作流图谱创作契约

## 快速路径

按这个有界顺序创作，不要一次性读遍所有参考资料：

1. **选图种**：`architecture`、`workflow`、`sequence`、`dataflow`、`lifecycle`。
   从问题本身选，不要从看起来最酷的图种选。
2. **写规格**：新建稳定的 ID、自己的领域措辞、清晰的布局。先有一条清楚的
   主路径，少量短旁支，稀疏标签，最多 12 个主节点。默认
   `meta.quality_profile = "showcase"`。
3. **每次改完都校验**：调用 `validate_diagram`。
   - showcase 通过必须报满 9 项工件检查，0 error、0 warning。
   - 只通过 4 项的规格只是基本校验，不等于 showcase 接受。
4. **交付只做一次**：调用 `deliver_diagram`。
   - 交付会把规格冻结成同目录快照，渲染并检查快照，再原子提交 HTML，
     并给出规格与产物各自的 SHA-256 与字节数。
   - 非零退出永远不能说成成功；交付失败会保留上一次产物，因此不要对那条
     路径做视觉检查——那会看到上一份好的产物，而不是失败的候选。
5. **只在用户要求预览时**：`render_mermaid` + 产物路径。

## 修什么，别修什么

- 诊断给出的是 `subject` 和 `supported_fixes`。一次只应用一处诊断出的几何
  控制：`via`、`label`、旁支数量、分层。
- 不要在诊断点名之前加 `via` 或 `labelAt`；也不要在散文里计划精确坐标。
- 通过最终校验的候选即被冻结，之后不要再改。

## 三条独立声明

- `deliver_diagram` 证明确定性工件检查通过。
- 产物自带的浏览器能力（主题、平移缩放、搜索、聚焦、视图、导出）是读者能力，
  不是额外的创作工作。
- 感知层面的视觉审阅需要真正的人或能读图的审阅者；插件不做这件事，也不声明
  这件事。

## Mermaid 导入

`convert_mermaid` 接受 `flowchart`/`graph`、`sequenceDiagram`、
`stateDiagram-v2` 三种输入，产出规格后走同一条校验与交付流水线。
导入只搬结构，不搬视觉决策；标签与 ID 需要你自己复核。

## 读者能力（无需作者操作）

产物 HTML 已内置：深浅主题、平移缩放、搜索、聚焦、关系追溯、语义视图、
真实的 SVG/PNG 导出。`meta.animation = "trace"` 是显式 opt-in；`meta.views`
最多放 5 个策展章节。
